# Sift

A self-hosted, infinitely scrolling feed of useful things to read and practise. It's a web app you add to your phone's home screen, backed by a free Supabase project and hosted on GitHub Pages. You choose the topics; nobody else's algorithm is involved.

**No LLM involved.** Everything is curated by rules you control:

- **Articles** come from sources you choose: RSS/Atom feeds (including YouTube channels, Substacks and blogs) and Hacker News. They're filtered by community score and include/exclude keywords, and ranked by source weight, recency and your own 👍/👎 history. Summaries are the feed's own description or the page's meta description.
- **Practice cards** fill the feed when there are no unread articles, so it never runs dry. They're generated by plain code and your own data:

| Card type | What it does |
|---|---|
| Flashcards | Spaced repetition (SM-2 style) from any deck you import (comma or tab separated, so pasting from a spreadsheet works). |
| Text cards | One random line from a list you paste in: practice prompts, tips, quotes, checklists. |
| Guitar chord shapes | Open, seventh, sus and movable barre chords, drawn as diagrams. Quiz mode: name first, then reveal. |
| Guitar scale shapes | A scale in one position, rooted on the E or A string. Note or degree labels. |
| Fretboard note finder | "Find G on string 5", then reveal. |
| Chord spelling | "Spell E♭m7", with correct enharmonic spelling, shown on a keyboard. |
| Key signatures | Signatures, relative minors, circle of fifths. |
| Ear training | Plays an interval through the phone speaker; name it. |
| Sight reading | Notes on a treble, bass or grand staff to name: single notes or short passages, with key signatures, accidentals and ledger lines. Tap to check, then hear them played. No instrument needed. |

Use only what you want. A feed with just news sources and no practice cards works fine, and so does the reverse.

## Make it yours: topics, sources and cards

A fresh install is **empty**. Open the app, go to **Settings → Topics** and either:

- **Add a starter pack**: ready-made topics with sources and card types (AI, Programming, Science, Russian, Guitar, Piano, Sight reading, Machine learning, UK news & Reading, International development, Biometrics, Cute animals). Add as many as you like, then edit or delete anything.
- **Add your own topic** and fill it in by hand.

Everything is edited in the app under **Settings**, with no code changes or redeploys:

| Tab | What you configure |
|---|---|
| Topics | Name, colour, and how often a slot is an article rather than a practice card. |
| Balance | The share of the feed each topic gets, as percentages that always add up to 100%. Moving one slider moves the others in proportion; lock a topic to hold its share. |
| Sources | Where articles come from, with include/exclude keywords, a minimum score (Hacker News), a maximum age, and a weight. **Preview** shows what a source would give you before you save it. |
| Card types | Which practice cards each topic gets, and their settings. |
| Decks | Flashcard decks. Paste lines of `front, back, note`, then add a *Flashcards* card type that points at the deck. |

### Choosing what you see

The feed has a **topic filter** (the button at the top right): search, tick any combination of topics, then apply. Your choice is remembered on that device.

While reading, tap **⋯** on an article (or its source name) to change what you see for good: hide the source, hide the site's domain (useful for Hacker News), show less or more from the source, hide the topic, or edit the source. Practice cards have it too: hide or rebalance a card type, hide its topic, or edit it. Each hide offers Undo. Muted domains are listed under Settings, next to Sign out.

Tapping an article's title opens it **in Sift**, in the app's own colours and fonts (dark mode included), with adjustable text size. YouTube videos play in place. If a page can't be read (paywalls, JavaScript-only sites), you get a button to open the original. Long-press a title to open the original directly.

### Managing lots of sources

Settings → Sources, Topics and Cards each have a search box, filters (topic, type, and status such as off, erroring or never fetched) and collapsible groups. Tap **Select** to tick many rows and act on them at once: turn on or off, move sources to another topic, set weight, fetch now, or delete.

### Reading in the app and muting domains

- **In-app reader**: opening an article extracts its readable text through the Edge Function (Mozilla Readability), strips it down to a strict allowlist of safe HTML and caches it in `item_content`, so it's fetched once. Feeds that publish full text (`content:encoded` or Atom `<content>`, 1,500+ characters) are stored at fetch time with no extra request. Pages that can't be extracted are recorded as failed and retried after 24 hours.
- **Muted domains**: a domain in `muted_domains` never appears in the feed (`feed_state` filters it out). Existing items are kept, just hidden.

### Tips for good sources

- **YouTube channel**: RSS source with `https://www.youtube.com/feeds/videos.xml?channel_id=CHANNEL_ID`. To find the ID, open the channel page and use *Share channel → Copy channel ID* (it starts with `UC`). Shorts are skipped automatically.
- **Substack**: `https://NAME.substack.com/feed`
- **Blogs**: try `/feed`, `/rss`, `/atom.xml` or `/feed.xml`, or look for the RSS link in the page source.
- **arXiv category**: `https://rss.arxiv.org/rss/cs.CL`. It's high volume, so add include keywords.
- **Lobsters tag**: `https://lobste.rs/t/TAG.rss` gives a community-voted link feed for tech topics.
- **Hacker News**: pick a keyword list for the topic and let the points threshold do the quality filtering.
- Reddit isn't supported: it blocks requests from cloud servers and its API needs approval.

### Writing your own starter packs

A pack is one JSON file in `public/starters/`. Add its filename to `public/starters/index.json` and it appears in the picker. It's worth doing if you want to share a setup with others or keep your own in version control.

```jsonc
{
  "name": "Chess",
  "description": "Shown in the picker.",
  "decks": [                                   // optional flashcard decks
    { "name": "Openings", "cards": [["e4 e5 Nf3 Nc6 Bc4", "Italian Game", "optional note"]] }
  ],
  "topics": [{
    "name": "Chess", "color": "#7c3aed", "weight": 2, "curated_ratio": 0.5,
    "sources": [
      { "kind": "rss", "name": "Some blog", "config": { "url": "https://example.com/feed", "max_age_days": 30 },
        "include": "", "exclude": "", "weight": 1 },
      { "kind": "hn", "name": "Hacker News: chess", "config": { "min_points": 100, "days": 3 },
        "include": "chess", "exclude": "", "weight": 1 }
    ],
    "cards": [
      { "kind": "flashcards", "name": "Openings", "weight": 2, "config": { "deck": "Openings", "new_per_day": 5 } },
      { "kind": "prompts", "name": "Practice", "weight": 1, "config": { "label": "Practice", "lines": ["Do 10 tactics puzzles."] } }
    ]
  }]
}
```

Source kinds are `rss` and `hn`. Card kinds and their `config` keys are defined in `public/lib/generators.js` (`flashcards`, `prompts`, `guitar_chord`, `guitar_scale`, `fretboard_note`, `piano_chord`, `key_signature`, `ear_interval`, `staff_notes`). `npm test` validates every pack and installs each one into a real schema, so mistakes show up before you deploy.

A pack only adds topics and decks whose names don't exist yet, so installing one twice is harmless.

## How it's hosted (all free tiers)

```
GitHub Pages ──── the app (static files in public/; Supabase URL + publishable key in public/config.js)
     │  supabase-js, signed in as you
     ▼
Supabase ──────── Postgres: all data; row level security lets only the owner account in (app_owner table)
                  Edge Function `sift-fetch`: Preview / Fetch now buttons, and the hourly fetch
                  pg_cron: calls sift-fetch every hour (secret generated in-database, kept in Vault)
GitHub Actions ── Deploy: run tests → (optionally push migrations + function) → publish Pages
```

The feed ranking, card generation and spaced repetition run in the browser (`public/lib/`). Fetching runs in the Edge Function (`supabase/functions/`); `npm run fetch` runs the same code locally.

It's a **single-user** app: one owner account per deployment. Each person who wants their own Sift forks the repo and creates their own Supabase project.

## Deploy your own

You need a [GitHub](https://github.com) account and a free [Supabase](https://supabase.com) account. Allow about 15 minutes. The Supabase CLI is needed for steps 2 and 3 (`npm install -g supabase`, or see the [install docs](https://supabase.com/docs/guides/local-development/cli/getting-started)).

### 1. Fork and clone

Fork this repository on GitHub, then clone your fork.

### 2. Create the Supabase project and apply the database

1. In the [Supabase dashboard](https://supabase.com/dashboard), create a new project. Note the **database password** you set and the **project ref** (the `abcdefgh` in `https://abcdefgh.supabase.co`).
2. From your clone:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push                      # applies supabase/migrations/ (schema, row level security, cron support)
supabase functions deploy sift-fetch  # the fetcher; it checks the caller itself, so no JWT check at the gateway
```

(No CLI? Paste each file in `supabase/migrations/` into the SQL editor in filename order, and deploy the function with any other method you prefer.)

### 3. Create your account and schedule the hourly fetch

1. **Authentication → Users → Add user → Create new user**: your email and a password, with *Auto Confirm User* ticked.
2. In the **SQL editor**, make that account the owner and schedule the fetch (replace both placeholders):

```sql
insert into app_owner (user_id) select id from auth.users where email = 'you@example.com';
select private.schedule_fetch('https://YOUR_PROJECT_REF.supabase.co');
```

No other account can read or change anything, even if sign-ups are on. Turning off *Allow new users to sign up* (Authentication → Sign In / Providers) is still tidy.

### 4. Publish the app to GitHub Pages

1. In your fork: **Settings → Secrets and variables → Actions → Variables → New repository variable**. Add:
   - `SUPABASE_URL`: your project URL, `https://YOUR_PROJECT_REF.supabase.co`
   - `SUPABASE_ANON_KEY`: the publishable key, from **Project Settings → API Keys** (`sb_publishable_…`, or the legacy `anon` key)

   Both are public by design (they ship to every browser). Your data is protected by row level security and your login.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. **Actions → Deploy → Run workflow** (or push any commit to `main`). When it finishes, the app is at `https://YOUR_USERNAME.github.io/YOUR_REPO/`.

### 5. Open it and add topics

Open the URL, sign in with the account from step 3, and follow the prompt to **Settings → Topics → Add starter pack** (or create your own topic). New sources are fetched immediately, and then every hour.

**On your phone**: open the URL, sign in, then **Add to Home Screen** (Safari share menu, or the Chrome ⋮ menu).

### Optional: deploy database and function changes from CI

By default you apply migrations and redeploy the function yourself when you pull updates (`supabase db push`, `supabase functions deploy sift-fetch`). To have every push to `main` do it for you, set the repository variable `SUPABASE_PROJECT_REF` and the secrets `SUPABASE_ACCESS_TOKEN` ([create one](https://supabase.com/dashboard/account/tokens)) and `SUPABASE_DB_PASSWORD`.

### Updating

Pull from the upstream repository into your fork, then apply new migrations (`supabase db push`), redeploy the function if it changed, and push. Your topics and data live in your Supabase database, so updates never touch them.

### Free-tier notes

- Supabase pauses free projects after about a week without activity. The hourly fetch should keep yours awake; if it pauses anyway, restore it from the dashboard.
- Everything here fits comfortably inside the free plans for a single user.

### Troubleshooting

- **Blank page, or "Can't start"**: the app shows what's wrong. Usually the `SUPABASE_URL` / `SUPABASE_ANON_KEY` variables are missing or wrong (the deploy fails with a message if they're unset). Fix them and re-run the workflow. **Clear cache and reload** helps if the phone is stuck on an old version.
- **Sign-in works but everything is empty or errors**: step 3's `insert into app_owner …` wasn't run, or used a different email.
- **A source shows an error**: open it in Settings → Sources and press **Preview**. The message says whether the feed URL, a redirect or your filters are the problem.
- **No new articles overnight**: check that `select private.schedule_fetch(…)` was run, and look at **Database → Cron** (or `select * from cron.job_run_details order by start_time desc limit 5;`).

## Development

Requires Node 20+ and a local Postgres.

```bash
npm install
createdb sift_dev
RESET_DB=1 DATABASE_URL=postgres://localhost/sift_dev npm run dev   # http://localhost:5173, any email/password signs in
```

`npm run dev` serves the app plus a minimal stand-in for the Supabase APIs the app uses, backed by your local Postgres with the real migrations and row level security. It's for UI work only; production talks to real Supabase. You can also use the official `supabase start` (Docker) with a `public/config.js` copied from `public/config.example.js`. `public/config.js` is gitignored; the deploy workflow writes it from the repository variables.

| Command | |
|---|---|
| `npm test` | Unit and database tests (needs Postgres; `TEST_DATABASE_URL`, default `postgres://postgres:postgres@localhost:5432/sift_test`). |
| `node test/e2e.cjs` | Browser end-to-end test against `npm run dev` (needs Playwright). |
| `npm run fetch` | Fetch all sources once from your machine (`DATABASE_URL` = a Postgres connection string). |

```
public/                       the app (vanilla JS, no build step)
  app.js                      UI: feed, saved, settings
  starters/                   starter packs (JSON) offered in Settings → Topics
  lib/feed.js                 ranking + building feed pages
  lib/generators.js           practice card kinds + spaced repetition
  lib/packs.js                validating and installing starter packs
  lib/balance.js              share-balancing maths for Settings → Balance
  lib/theory.js               music theory (spelling, chords, scales, keys, chord shapes)
  lib/data.js                 all Supabase reads/writes
supabase/migrations/          schema, owner-only row level security, feed_state(), hourly cron support
supabase/functions/sift-fetch Edge Function (preview / fetch now / hourly fetch)
supabase/functions/_shared/   fetcher (RSS/Atom, HN, filtering, de-dup) + database writes
scripts/fetch.js              fetch once from the command line
.github/workflows/deploy.yml  tests + GitHub Pages (+ optional Supabase deploy)
```

Ranking is `source weight × community score factor × recency decay × your affinity for that source × your affinity for that domain`. Articles are marked read once they have been at least half on screen for about a second, and they never show again.
